# 📰 TelegaNews

Telegram-бот, который автоматически собирает новости из Telegram-каналов, хранит их в векторной базе данных (PostgreSQL + pgvector) и по запросу пользователя генерирует ИИ-сводку по выбранной теме за выбранный период.

**Идея в двух словах:** фоновый парсер каждый час обходит каналы, превращает каждый пост в вектор-эмбеддинг (локальная модель `cointegrated/rubert-tiny2`, 312 измерений) и складывает в БД. Пользователь бота выбирает тему и период (14 или 30 дней) — бот находит в базе семантически близкие посты (косинусная близость по HNSW-индексу), собирает их в контекст и отправляет во внешнюю LLM-прокси, которая пишет связную сводку с ссылками на первоисточники.

---

## Возможности

- 🤖 Telegram-бот на aiogram 3: выбор темы → выбор периода → сводка
- 📡 Парсинг Telegram-каналов через аккаунты (Pyrogram), ротация сессий
- 🛡 Обход флуд-банов: `block_time` временно исключает аккаунт из ротации
- 🗃 Дедупликация постов на уровне БД (`UNIQUE (channel, message_id)`)
- 🧹 Автоматическая очистка истории старше 60 дней
- 🔍 Семантический поиск: pgvector + HNSW-индекс, косинусная метрика
- ⚙️ Промпты для LLM хранятся в БД — менять их можно без передеплоя
- 🐳 Docker-развёртывание (2 контейнера) + CI/CD через GitHub Actions

```
│  Parser      │ ─────► │  PostgreSQL         │ ◄───── │  Bot          │
│  (Pyrogram + │        │  + pgvector         │        │  (aiogram 3)  │

│   раз в час) │        └─────────────────────┘        └───────┬───────┘
└──────┬───────┘                                              │
       │  Telegram API (парсинг каналов)                      │ RAG: векторный
       └─────────────────────────────┐                        │ поиск + контекст
                                     ▼                        ▼
                          ┌────────────────────────┐  ┌──────────────────┐
                          │  LLM Proxy API         │◄─┤  services/       │
                          │  (внешний сервис,      │  │  search_news.py  │

```

Проект состоит из трёх логических частей:

| Компонент | Файл | Роль |
|---|---|---|
| **Парсер** | `parser.py` | Фоновый воркер с планировщиком (APScheduler, интервал 1 час). Забирает из БД каналы (не более 7 за итерацию), парсит до 100 последних сообщений (окно 30 дней), векторизует их и пишет в `history`. Также очищает записи старше 60 дней. |
| **Бот** | `bot.py` | Telegram-бот. Диалог: `/start` → выбор темы → выбор периода (14/30 дней) → генерация сводки. Состояние хранится в FSM. |
| **RAG-слой** | `services/search_news.py` | Семантический поиск по `history` (косинусная близость к описанию темы) и сборка контекста; кастомный LLM-класс LangChain (`TgProxyLLM`) для обращения к внешнему прокси с ретраями (3 попытки, экспоненциальная пауза) и таймаутом 120 с. |

### Поток данных

1. **Парсер** каждые 60 минут: берёт свободные сессии (`block_time` в прошлом) и каналы, которые ещё не проверялись сегодня (`last_checked_at`).
2. Для каждого сообщения канала за последние 30 дней считает эмбеддинг моделью `rubert-tiny2` и вставляет в `history`. Дубликаты (`channel` + `message_id`) игнорируются БД.
3. **Пользователь** жмёт `/start` — бот читает список тем из `topics`.
4. После выбора периода бот берёт развёрнутое описание темы, ищет по нему семантически близкие посты за N дней (`get_context_from_db`), формирует из них контекст со ссылками вида `https://t.me/{channel}/{message_id}`.
5. Шаблон промпта читается из таблицы `prompts` (проект `tg_news`), в него подставляются `{short_history}` (найденные посты) и `{topic}` (описание темы).
6. Цепочка LangChain (`prompt | llm`) вызывает LLM-прокси, результат отдаётся пользователю.

## База данных

**PostgreSQL** с расширением **pgvector**. Подключение настраивается переменными `POSTGRESQL_*` (см. раздел «Переменные окружения»). СУБД — внешняя по отношению к docker-compose (в compose поднимаются только бот и парсер).

Все таблицы находятся в схеме `tg_ai`, кроме `prompts` — она в схеме `public`.

### Таблицы

#### 📌 `channels` (схема `tg_ai`) — каналы для парсинга

| Поле | Тип | Описание |
|---|---|---|
| `channel_id` | Integer, PK | Автоинкремент |
| `channel` | String, unique-index | Имя канала (`username`) или invite-ссылка (`t.me/+xxxx`) |
| `last_checked_at` | Date, nullable | Дата последней успешной проверки; парсер берёт только каналы, у которых дата не равна сегодняшней |

**Зачем:** реестр источников новостей. `last_checked_at` позволяет распределять проверку каналов по дням — за одну итерацию обрабатывается не более 7 каналов, остальные ждут следующего часа/дня.

#### 🔑 `sessions` (схема `tg_ai`) — Telegram-аккаунты для парсинга

| Поле | Тип | Описание |
|---|---|---|
| `user_id` | Integer, PK | Автоинкремент |
| `user_name` | String, index | Имя клиента (используется как `name` клиента Pyrogram) |
| `api_id` / `api_hash` | String | Ключи Telegram API аккаунта |
| `session` | String, nullable | Готовая строка сессии Pyrogram (Base64). Если пуста — генерируется при локальном запуске парсера (интерактивная авторизация) |
| `block_time` | Integer, nullable | Unix-время, до которого аккаунт исключён из ротации (флуд-бан, ошибка 420) |

**Зачем:** парсинг через пользовательские аккаунты позволяет читать каналы без Bot API и без ограничений на количество каналов. Сессии ротируются случайным образом, а `block_time` даёт аккаунту «отлежаться» после флуд-бана.

#### 📋 `topics` (схема `tg_ai`) — темы для бота

| Поле | Тип | Описание |
|---|---|---|
| `topic_id` | Integer, PK | Автоинкремент |
| `topic` | String, index | Короткое название темы (кнопка в боте) |
| `description` | String | Развёрнутое описание темы — используется как векторный запрос для поиска релевантных постов |

**Зачем:** именно по описанию темы (а не по названию) считается эмбеддинг-запрос — чем подробнее описание, тем точнее семантический поиск по новостям.

#### 🧠 `prompts` (схема `public`) — шаблоны промптов

| Поле | Тип | Описание |
|---|---|---|
| `prompt_id` | Integer, PK | Автоинкремент |
| `project_name` | String, index | Идентификатор проекта (бот ищет `'tg_news'`) |
| `prompt` | String | Текст промпта — **обязательно** с плейсхолдерами `{short_history}` и `{topic}` |

**Зачем:** промпты вынесены в БД, чтобы редактировать поведение LLM (тон, структуру сводки, правила цитирования) без передеплоя бота — достаточно обновить строку в таблице.

#### 📰 `history` (схема `tg_ai`) — посты и их векторы

| Поле | Тип | Описание |
|---|---|---|
| `history_id` | Integer, PK | Автоинкремент |
| `date` | DateTime, index | Дата публикации поста |
| `channel` | String, index | Канал-источник |
| `message_id` | Integer, index | ID сообщения в канале (для ссылки `t.me/{channel}/{message_id}`) |
| `message` | String | Текст поста (или подпись к медиа) |
| `message_emb` | `vector(312)` | Эмбеддинг текста моделью rubert-tiny2 |
| `created_at` | DateTime | Дата записи в БД (проставляет сама БД, `server_default=now()`) |

Дополнительно:
- **HNSW-индекс** `hnsw_idx_history_emb` (`vector_cosine_ops`, m=16, ef_construction=64) — ускоряет косинусный поиск на больших объёмах.
- **`UNIQUE (channel, message_id)`** — защита от дубликатов на уровне БД (вставка через `INSERT ... ON CONFLICT DO NOTHING`).
- **Retention:** парсер раз в итерацию удаляет записи с `date` старше 60 дней.

**Зачем:** это «корпус новостей» для RAG — весь семантический поиск идёт только по этой таблице. Векторы позволяют искать по смыслу, а не по ключевым словам.

### Инициализация схемы

В коде нет автоматического создания таблиц (`Base.metadata.create_all` не вызывается) и миграций alembic, поэтому при первом развёртывании выполните вручную:

```sql
CREATE EXTENSION IF NOT EXISTS vector;   -- pgvector
CREATE SCHEMA IF NOT EXISTS tg_ai;
```

и создайте таблицы через SQLAlchemy (модели в `models/mdl_tables.py`):

```python
import asyncio
from database.db_loader import engine
from models.mdl_tables import Base

async def create_tables():
    async with engine.begin() as conn:
        await conn.run_sync(Base.metadata.create_all)

asyncio.run(create_tables())
```

После этого заполните стартовые данные: каналы, темы, промпт и хотя бы одну сессию.

## Установка и запуск

### Локальная разработка

```bash
# 1. Виртуальное окружение и зависимости
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# 2. Конфигурация
cp .env.example .env   # или создайте .env по таблице выше

# 3. Подготовить БД (см. раздел «Инициализация схемы»)
#    + скачать модель эмбеддингов (сделается сама при первом запуске)

# 4. Запустить парсер (при первом запуске создаст сессию Pyrogram
#    — потребуется ввести код авторизации от аккаунта)
python parser.py

# 5. В другом терминале — бот
python bot.py
```

> **Важно про сессии:** в Docker сессии не генерируются — парсер использует только готовые строки из БД. Поэтому перед деплоем получите строку сессии локальным запуском `parser.py` (или отдельно — `get_session` в `parser.py`) и положите её в таблицу `sessions`.

### Docker

```bash
# Сначала собрать базовый образ с зависимостями (общий для бота и парсера)
docker build -f Dockerfile.base -t teleganews-base:latest .

# Затем собрать и поднять сервисы
docker compose up -d --build
```

`docker-compose.yml` поднимает два контейнера (`telega_bot`, `telega_parser`) в общей сети, оба читают `.env` и перезапускаются при падении (`restart: always`). PostgreSQL остаётся внешним.

### Деплой на сервер (GitHub Actions)

Workflow `.github/workflows/deploy.yml` срабатывает на пуш в ветку `main` (или вручную через `workflow_dispatch`):

1. По SSH подключается к VDS (секреты `VDS_HOST`, `VDS_USER`, `VDS_SSH_KEY`).
2. `git fetch` + `git reset --hard origin/main` (локальные правки на сервере сбрасываются).
3. Чистит Docker-кэш, собирает `Dockerfile.base` (зависимости ставятся один раз).
4. `docker compose build && docker compose up -d`.

## Использование бота

1. Отправьте боту `/start` — появится клавиатура с темами (из таблицы `topics`).
2. Выберите тему — бот спросит период: **за 14 дней** или **за 30 дней**.
3. Бот найдёт релевантные посты и сгенерирует сводку (обычно 1–2 минуты), результат придёт в то же сообщение.

Если релевантных новостей за период нет — бот честно сообщит об этом.

## Замечания и известные ограничения

- **Модель эмбеддингов не попадает в Docker-образ.** Парсер работает в offline-режиме (`HF_HUB_OFFLINE=1`), но в `Dockerfile.base` нет шага скачивания `cointegrated/rubert-tiny2` — на свежем сервере контейнер парсера упадёт при старте. Рекомендуется добавить в `Dockerfile.base`:
  ```dockerfile
  RUN python -c "from sentence_transformers import SentenceTransformer; SentenceTransformer('cointegrated/rubert-tiny2')"
  ```
- **Схема БД не создаётся автоматически** — см. «Инициализация схемы».
- **Разметка ответов бота** — `Markdown` (legacy): текст от LLM с `*`, `_`, `[` может сломать парсинг Telegram. При частых ошибках стоит перейти на HTML или экранировать MarkdownV2.
- **`prompts` в схеме `public`**, остальные таблицы — в `tg_ai`. При желании единообразия перенесите её в `tg_ai`.
- Промпт в `prompts` обязан содержать плейсхолдеры `{short_history}` и `{topic}` — без них сборка цепочки LangChain упадёт.
